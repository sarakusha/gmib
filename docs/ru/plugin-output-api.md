# Plugin API 1.2: управление выводом и плеерами

Доступно начиная с GMIB 5.7.1. Плагин с новыми методами указывает
`gmibApi: "^1.2.0"`. Более старые хосты отклоняют такой манифест до запуска.
Ранее опубликованные плагины с `^1.0.0` и `^1.1.0` продолжают работать.
В SDK новые методы помечены необязательными, чтобы переносимый код мог проверить
их наличие до вызова. Интерфейс управления удалённым GMIB проверяет версию хоста:
установка, обновление, включение и открытие пульта плагина с `player.control`
недоступны на хостах ниже 5.7.1; отключение и удаление остаются доступны.

## Разрешения

- `output.control`: `context.output.listScreens/getStatus/start/stop/applyLayout`.
- `player.control`: `context.output.listPlayers/setPlayerState` и изменения плееров в `applyLayout`.

Разрешения независимы и проверяются при каждом вызове. Одного `output.control`
недостаточно для доступа к плеерам. Для сценария «часы рядом с рекламой» нужны оба.
Установка или обновление плагина с новым разрешением требует принятия точного
набора разрешений обычным диалогом GMIB. Доступ к БД GMIB или произвольным внутренним
HTTP-маршрутам плагину не предоставляется.

## Методы

```ts
await context.output.listPlayers();
// [{ id: 7, name: "Реклама", playing: false }]

await context.output.setPlayerState({ playerId: 7, playing: true });
await context.output.setPlayerState({ playerId: 7, playing: false });
```

`playing` в списке отражает сохранённый флаг автоматического воспроизведения;
это не подтверждение физического изображения на дисплее.

При `playing: true` хост проверяет плеер и выбранный плейлист, сохраняет состояние
воспроизведения, при необходимости создаёт локальный плеер скрытым и показывает
его настроенные окна вывода. Главная вкладка/окно GMIB не активируется и не
разворачивается. Наличие локальной вкладки управления GMIB не требуется, в том числе
при автозапуске плагина до создания главного окна. Существующий плеер используется без
повторного открытия вкладки.
При ошибке создания плеера исходное состояние воспроизведения восстанавливается.
При `playing: false` хост останавливает воспроизведение, сбрасывает текущий элемент
и скрывает окна вывода этого плеера; вкладка плеера не закрывается.
Геометрия окон и плейлисты настраиваются штатными средствами GMIB.

Метод возвращает `Promise<void>`. Ошибки: нет разрешения, некорректные аргументы,
плеер удалён, плейлист не выбран, запуск или сохранение
не удались. Успех означает применение состояния, но не гарантирует наличие
подключённого физического дисплея или воспроизводимого файла.

Методы `start`, `stop`, `setPlayerState` и `applyLayout` выполняются последовательно
для каждого экземпляра плагина. Между отдельными вызовами нет общей транзакции.
Необязательный `applyLayout({ profile, players })` согласованно меняет экран и состояния
плееров: старый вывод остаётся впереди до готовности нового экрана и первого кадра
запускаемых плееров. При ошибке хост восстанавливает предыдущие экран и состояния
плееров. Восстановление выполняется по возможности: если прежняя страница сама перестала
загружаться, подготовленный новый экран остаётся, а ошибка содержит и причину отказа, и причину
неполного восстановления. Не вызывайте `stop` перед ним. Готовность первого кадра ожидается до 8 секунд:
если кадр не появился, хост сохраняет прежний вывод и возвращает ошибку.
Перед передачей показа также проверяется готовность изображения нового экрана и выдерживается
пауза 500 мс для его появления на дисплее. Пауза действует на всех платформах, включая Windows.
Если дисплей
целевого экрана отключён или страница не загрузилась, прежний работающий экран остаётся на месте.
Новая глобальная команда видимости GMIB отменяет незавершённое переключение; откат не отменяет
эту команду и не показывает заново скрытые ею окна.

`players` необязателен. Непустой список требует `player.control`, пустой список — только
`output.control`. Идентификаторы и состояния всего списка проверяются до изменений; один плеер
не может повторяться в списке. Остановка уже удалённого плеера допустима как очистка старого
назначения, запуск удалённого плеера возвращает ошибку. Состояния запускаются и подтверждаются
до остановки плееров из той же команды; профиль автозапуска сохраняется последним.
Без этого метода плагин сам сериализует
составную команду и обрабатывает частичные ошибки. Разные плагины могут управлять
одним плеером; эксклюзивной блокировки плееров в API 1.2 нет.

## Эксклюзивный экран

`output.start({ screenId, pageId, autoStart })` сначала подготавливает и показывает
выбранный экран, затем скрывает прежние экраны этого плагина. Чужие плагины не отключаются; занятый
чужим плагином целевой экран приводит к ошибке. `output.stop()` очищает все экраны,
принадлежащие плагину. Это не останавливает плееры автоматически: вызывайте
`setPlayerState` для управляемого плеера явно.

`output.getStatus().active` учитывает назначение страницы, подключение дисплея
и фактическую видимость окна. Показ экрана выполняется через `showInactive`.
Явный показ плагином действует на выбранные экран и плеер даже после глобального
скрытия; другие окна остаются скрыты. Следующая глобальная команда видимости GMIB
снова имеет приоритет. На Wayland отсутствие фокусировки зависит от ограничений
Electron/оконного менеджера.

## Пример переключения

```ts
if (context.output.applyLayout) {
  // Компактный экран и реклама рядом: прежний вывод остаётся до готовности нового.
  await context.output.applyLayout({
    profile: { screenId: 2, pageId: "screen", autoStart: true },
    players: [{ playerId: 7, playing: true }],
  });

  // Широкий экран и остановка рекламы одной командой.
  await context.output.applyLayout({
    profile: { screenId: 1, pageId: "screen", autoStart: true },
    players: [{ playerId: 7, playing: false }],
  });
}
```

При автозапуске `output.start` восстанавливается хостом из профиля `gmib.output`.
Привязку плеера и составную команду автозапуска плагин хранит и восстанавливает сам.

## Удалённый пульт

С GMIB 5.7.1 пульт можно открыть из раздела «Плагины» удалённого подключения.
GMIB предоставляет авторизованный шлюз и временный loopback-прокси: обычные относительные
`/plugins/<id>/api/…` URL и WebSocket на корне продолжают работать. Браузеру не выдаются
секреты подключения. `localOnly: true` запрещает такой пульт и через туннель; управление
установкой/отключением/удалением остаётся доступно. Прямые local-маршруты по LAN не открываются.
Прокси действует до закрытия подключения; для постоянного локального PWA используйте адрес
GMIB на том же компьютере.
