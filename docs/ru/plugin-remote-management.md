# Удалённое управление плагинами — GMIB 5.7.1

Откройте подключение к удалённому GMIB и его раздел «Плагины». Список, официальный каталог,
установка из файла, обновление, включение, отключение, удаление и перезапуск относятся к
выбранному узлу. Для установки показывается его адрес, точный набор разрешений и предупреждение
о доверенном backend. Локальный GMIB при этом не изменяется.

Нужны GMIB 5.7.1 или новее на управляющем компьютере и удалённом узле, авторизация подключения
и лицензия с поддержкой плагинов на целевом узле. Для старых хостов раздел скрыт; при отсутствующем
endpoint выводится предложение обновить GMIB. Версия берётся из фактической сессии подключения.

## Авторизация

Main-процесс определяет узел по зарегистрированному отправителю IPC, а не по адресу из команды
renderer. Запросы используют существующую авторизацию GMIB (подпись SRP; локально Bearer).
Все маршруты `/api/manage/v1/plugins` требуют авторизацию, в том числе при включённом `unsafeMode`.
Файловая установка передаёт архив с SHA-256; согласие пользователя относится к тем же байтам,
версии и набору разрешений, которые затем устанавливаются. Удалённый перезапуск использует
`POST /api/manage/v1/plugins/restart`.

Подпись запросов не шифрует HTTP-трафик. Для доступа через недоверенные сети используйте
существующий защищённый канал подключения, VPN или SSH-туннель.

## Пульт в браузере

GMIB открывает временный прокси на `127.0.0.1` со случайным портом и сессионным HttpOnly cookie.
Он привязан к одному плагину выбранного узла. Секреты авторизации остаются в main-процессе;
браузер их не получает. Запросы с чужим Origin, без cookie, к другому плагину или с неоднозначным
путём отклоняются. Прокси закрывается при закрытии окна подключения или повторном открытии того
же пульта. После этого откройте пульт заново из «Плагинов».

Удалённый шлюз `/api/manage/v1/plugins/:id/control` предоставляет:

- `/static/*` — публичные файлы выбранного плагина;
- `/api/*` — зарегистрированные JSON-маршруты `local` и `authenticated`;
- `/events` — поток NDJSON только событий `plugin:<id>:…` выбранного плагина.

В браузере сохраняются обычные пути `/plugins/<id>/…`. WebSocket на корне прокси получает
события через авторизованный поток; команды отправляются через JSON API. Тела запросов и ответов
ограничены 20 МиБ. Сторонние cookies и заголовки CORS не пересылаются, HTTP-переадресации удалённого
узла не разрешены. Прокси предназначен для пульта в текущей сессии, а не для постоянного адреса PWA.

`localOnly: true` запрещает удалённый пульт, статические файлы и события через шлюз, даже если
соединение приходит через loopback/туннель. Отключить или удалить такой плагин удалённо можно.
Обычные `/plugins/:id/api/*` маршруты с доступом `local` по-прежнему принимают запросы только
с loopback; шлюз не меняет это правило и открывается только после авторизации GMIB.
